## What is measured

`vitest.config.ts` sets `coverage.include: ['src/**/*.{ts,tsx}']`. **Do not remove
it.** Without `include`, the v8 provider reports only files that a test happened
to load, so an untested module is absent from the report rather than scored 0% —
and every threshold below becomes unfailable. That was the case until this was
added: the report contained 3 files, showed 100%, and could not fail.

Currently measured: `src/app/page.tsx`, `src/hooks/use-mobile.ts`,
`src/lib/utils.ts` — 15 statements, 13 lines, 6 functions, 0 branches.

Excluded, with reasons:

- **`src/app/components/ui/**`** — 61 vendored shadcn/ui primitives, generated by
  the shadcn CLI rather than authored here. Add real logic to one and it should be
  carved out of that glob and tested. (`button.tsx` has a spec either way; the
  tests run whether or not the file is instrumented.)
- **`src/app/layout.tsx`** — module-level code that neither test environment can
  meaningfully execute.
- **`scripts/**`** — repo tooling, not shipped app code. `check-coverage-regression.ts`
  has its own spec regardless.
- Config files, `.d.ts` declarations, `types/**`, `setupTests.ts`, CSS, build
  output, and the spec files themselves.

## Coverage Targets

- **Minimum:** 95% on every metric, enforced by `coverage.thresholds` in
  `vitest.config.ts`.
- **Ideal:** 100% on all measured files.

### Regression policy

`pnpm run test:coverage:check` compares the run against the baseline table above:

- **Tolerance:** a drop of up to **2%** on any metric is permitted.
- **Floor:** the result must still sit above the 95% threshold.

Both conditions apply, so whichever binds first governs — the effective floor is
`max(baseline - 2, 95)`, and it moves with the baseline. At a baseline of 100% the
tolerance binds and the floor is **98%**; at a baseline of 96% the 95% threshold
binds instead.

- ✅ 100% → 98.5% (within tolerance, above threshold)
- ❌ 100% → 97.5% (exceeds the 2% tolerance)
- ❌ 96% → 94.5% (within tolerance, but below the 95% threshold)

When a drop breaches both bounds the threshold is the one reported, so
`97% → 94.5%` fails as "below threshold of 95%" even though it also exceeds the
tolerance. Each bullet above is a test case in `scripts/coverage-gate.spec.ts`.

Note this file is the baseline for a **delta** check only: a metric at or above
its baseline passes here however low the baseline is. The absolute floor is
`coverage.thresholds` in `vitest.config.ts`, enforced by Vitest itself, which
runs first in `pnpm run test:coverage:check`.

## How to update

```bash
pnpm run test:coverage        # writes coverage/ and prints the summary
pnpm run test:coverage:check  # compares against the baseline above
```

`check-coverage-regression.ts` rewrites the summary table and the date for you;
add a Coverage History row by hand when the number moves for a reason worth
recording.
